# LightBenchmark 2

1モデルの4課題を1ページにまとめ、実行回を選んで生の回答・実測・再生を確認する。旧結果は archive に残す。参考モックをモデルの成績へ転用しない。

2026-09-21のユーザー指示により、今回の作業はプラットフォームの実装・公開までとする。LLMへの実際の呼び出しは別作業で行い、費用確認やモデル実行を公開の前提にしない。

## 実行と提出

各課題は独立した新規会話で一度生成する。同じプロンプト、出力上限、実行上限、評価seed集合を全モデルへ適用し、条件のhashを記録する。GoモデルIDを指定できるCLIとOpenAI互換APIを用意する。秘密情報、個人のルール、参考解答、評価器を候補へ渡さない。

日本語は「ギャルっぽく糸島を紹介して」への原文をそのまま保存・全文表示。自然さ・ギャル口調・事実性は人の評価を別に保存し、未採点を0点にしない。

コード課題は依存なしのES moduleを提出する。QuickJSの独立したWASM実行環境で動かし、ホスト機能・モジュール読込を公開しない。メモリ上限と割込みに加え、外側のworkerを時間制限で停止する。ブラウザの初期化も同じ候補コードと評価器で新しいseedを実行する。

## 課題API

- ぷよ: `plan(seed)` が35組の配置と発火1組を返す。`dropPair(board,pair)` と `resolve(board)` も候補が実装する。6×14、y=0が下、4色、4個以上の直交連結で消去。独立評価器で合法配置・途中消去なし・18連鎖72個全消しを検証する。初期化は空盤面から計画を再生成し、連鎖を約1秒ずつ再生する。
- キューブ: `scramble(seed)`、`applyMove(state,move)`、`solve(state)`、`animate(move,t)`。54整数の面順U/R/F/D/L/B。解く側は別実行環境でstateだけを受け取り、生成履歴を渡さない。独立生成した盤面でも検証する。各手の回転軸・層・途中角度を候補が返し、共通カメラと形で描画する。
- アーム: 共通のPlanck物理に対し `reset(config)`、`step(observation,dt)` が3関節の速度指令と指の開き幅を返す。観測は角度・角速度・各物体の姿勢・接触。候補は位置や成否を書き換えられない。中28×22cm、小19×16cm、大38×26cmを下から中→小→大に積み、解放・退避後3秒安定で成功。初期配置はseedで変える。段数、落下、衝突、時間、労力を別記録する。

## 保存と公開

実行ごとに追記専用ディレクトリを作り、モデルID、日時、要求本文、応答原文、候補コード、usage、所要時間、評価器バージョン、各seedの成績と再生ログを保存する。取得不能な費用・tokenはnull。モデル失敗と接続・評価基盤の失敗を分ける。

静的サイトを既存のpublic GitHub repositoryとPages workflowから公開する。実行器はローカルCLIで起動し、サイトには認証情報を置かない。新しい実行を追加してbuild/pushすると一覧を更新する。

外部で生成した4課題の回答をJSONで受け取り、APIキーなしで採点・記録できる。生成条件は申告として表示し、実行条件hashとの一致を確認する。未実測時の入口は4課題の未実測表示と動作デモへのリンクを用意する。デモは `demo/` に分離し、実測データ一覧へは入れない。

## 完了条件

外部回答の取り込みから独立採点・記録・モデル別4課題表示・公開までの経路を検証する。未実測状態と参考デモを明示して公開し、後から実測を追加できること。全回答、失敗を含む成績、履歴、初期化と再生が使えること。共通部品だけが解いてしまう構成にしない。独立評価・実行器の時間/メモリ/能力境界・データ検証・公開画面を検査する。LLM呼び出しと実モデル同士の測定は別作業へ引き継ぐ。
